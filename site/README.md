# ThemeAves

The public website for ThemeAves, a studio that builds self-hosted software.

This directory is the deployable site and nothing else. It is intended to be public.

## Documentation

`docs/` describes the current state; `BUILD.md` is the history and the reasoning. **When either
disagrees with the code, the code is right.**

## Status

The visual system is **direction 1a "Blueprint"**: cool neutrals plus a single accent derived from
the mark's own navy, Archivo and IBM Plex, structure carried by hairlines and a visible grid rather
than by cards or shadows.

**Eleven artefacts prerender**, all reviewed in both themes at 1440 / 1024 / 768 / 390:

`/` · `/products` · `/products/slotdesk-ai` · `/products/aonomy` · `/demos` · `/support` ·
`/license` · `/licenses` · `/_dev/brand` · `404` · `/manifest.webmanifest`

Not built, and blocked on content rather than on design or the stack: `/docs`, `/changelog`,
`/about`, `/terms`, `/privacy`, `/refunds`. Every blocker is a ❌ row in `../docs/FACTS.md`.
`/docs` and `/changelog` are launch blockers, because the homepage claims the documentation is
public and that every release is dated.

The component kit step was **skipped on instruction**. The cost is that component decisions were
made inside pages rather than argued in isolation, and only `/support` uses the page grammar in
`primitives.tsx`. A later kit pass will have to touch every route.

## Stack

Next.js 16 (App Router), TypeScript, Tailwind CSS v4, statically rendered. MDX content lands with
the product template.

```bash
npm install
npm run dev             # http://localhost:3000
npm run build
npx next start -p 3210  # the port the screenshot tooling assumes
npm run typecheck
npm run icons           # regenerate the icon set from public/brand/favicon.svg
```

**Never call a UI change done without rendering it and looking at the image.**

```bash
node ../tools/shot.cjs http://localhost:3210/ home   # then OPEN ../shots/*.png and LOOK
```

## What must never land in here

- **Unresolved facts written as if they were real.** Prices, version numbers, release dates, URLs,
  response windows and support hours are tracked as open blanks in `../docs/FACTS.md`. Ship a
  visible placeholder instead of a plausible guess. A wrong price in a public repo is a wrong price
  a buyer can quote back at you.
- **Design mockups presented as product screenshots.** The live demo is one click away and the
  difference gets noticed.
- The brainstorm, the research, the design commissions, the rejected attempts, the correction notes
  and the screenshot tooling. That work is candid about what failed and what is still unknown, which
  is useful internally and unhelpful in public.

## ⚠️ The separation is not structural yet

There is one git repository and its root is `/var/www/html/themeaves`, one level up. There is no
`.git` in this directory and no `.gitignore` at the repository root, so `../_dev`, `../docs`,
`../brand` and `../shots` are all inside the repository and stageable, and the repository has an
`origin` remote.

Until that is resolved, the separation is a matter of discipline rather than structure. Resolving it
is a git operation and therefore the user's to run. The two options are to make this directory its
own repository, or to add a root `.gitignore` that excludes the private directories and confirm
nothing private is already in the history.
